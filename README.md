# claude-planner

MCP-планер для Claude Code: план с детерминированными проверками, разведка на Haiku, исполнение воркерами Sonnet, независимая приёмка. Сделан по образцу `agy-planner`, но без обязательного плана на мелочи, вики-гейта и привязки к agy. Чистый Python 3.11+, без зависимостей.

## Идея

- **Состояние вне контекста.** План лежит в `<проект>/.cplan/plan.json` и переживает компактацию и рестарт сессии. Каталог сам прячет себя от git.
- **Закрыть пункт можно только проверкой.** `done` ставит не модель, а прогон `verify` с логом в `.cplan/evidence/`. Пустышки (`echo`, `true`, `ls`, `|| true`) и «проверка кода наличием файла» отвергаются при создании плана.
- **Воркеры — облегчённые сессии `claude -p`.** Без пользовательских настроек, MCP и `CLAUDE.md`: около 5–7 тыс. токенов контекста на старте против ~47 тыс. у обычного субагента. Нужные срезы кода (`путь:L10-L80` из `context`) вшиваются в промпт заранее.
- **Надзиратель вместо оркестратора.** Отдельный процесс на каждого воркера: запустил → прогнал проверки пункта → при провале вернул лог в ту же сессию воркера → проверил снова. Оркестратор на этот цикл токенов не тратит.
- **План есть всегда, вес — по задаче.** Нужен ли план, решает хук, а не модель: правка файла проекта без открытого плана отклоняется. Модель выбирает только вес — пункт без проверки для мелочи, пункт `main` с проверкой своими руками или пункты воркерам, с разведкой и приёмкой (приёмка включается сама от 4 пунктов) — и меняет его по ходу через `plan_update`.

## Ветка, файлы и граф кода

- План запоминает ветку git (`branch`). В другой ветке того же рабочего дерева хук отклоняет правки, а `plan_run` не стартует пункты; перенос — `plan_update(branch="<текущая>")`. Отдельный worktree под проверку не попадает.
- Воркер получает разрешения только на файлы своего пункта: `--allowedTools "Edit(//абсолютный/путь)"` на каждый (правило покрывает и `Write`; проверено на Claude Code 2.1.322 с `--permission-mode dontAsk`). Запись в обход, через Bash, этим не закрыта — её по-прежнему ловит надзиратель («правил вне пункта»).
- `planner/graph.py` спрашивает локальный `codegraph`, кто использует файлы пунктов. Работает только при готовом индексе `.codegraph` в проекте; без него молчит. Даёт предупреждение о связанных пунктах одной волны и строку «кто использует эти файлы» в промпте воркера.

## Документация

Вики обязательна от 4 пунктов с проверкой (`"docs": "always" | "big" | "off"` в `~/.config/claude-planner/config.json`, по умолчанию `big`). Режим плана перекрывает политику: `plan_init(docs=true)` — меняется запуск, контракт или схема; `docs=false` — багфикс или рефакторинг.

`wiki_publish(title, notes)` без `markdown` отдаёт страницу воркеру на Haiku (тир `docs`): он получает цель и пункты плана с результатами проверок, отчёты исполнителей, дифф, заметки оркестратора и текущий текст страницы, если она уже есть. Оркестратору возвращаются ссылка и оглавление. Секреты маскируются при публикации.

## Пункты без проверки

Для ограниченного набора ситуаций пункт можно завести без `verify`: `{"title": "…", "light": "debug" | "spike" | "nocode" | "trivial" | "followup"}` — отладка, эксперимент, не код, мелкая правка в одном файле, доделка. Такой пункт делает основная сессия и закрывает записью `plan_verify(item_ids, note="что сделал")`; в плане и на панели он помечен «без проверки». План из одних таких пунктов — чеклист: без приёмки, вики и задачи в Plane, три вызова от начала до конца. Границу держит хук: один файл кода на пункт, дальше нужен пункт с проверкой. Стоит дать пункту `verify` — он становится обычным.

## Тиры

| Тир | Модель | Права | Когда |
|---|---|---|---|
| `scout` (`plan_scout`) | Haiku | только чтение | разведка до планирования |
| `code-mini` | Haiku | правка | механика по образцу в нескольких местах: переименование, однотипные правки. Не прошёл проверки после доработки — пункт сам перезапускается на `code-low` |
| `code-low` | Sonnet, effort low | правка | простая реализация по образцу |
| `code` | Sonnet, effort medium | правка | обычная реализация и багфикс |
| `code-high` | Sonnet, effort high | правка | ветвистое, кросс-модульное |
| `review` (`plan_review`) | Opus, effort medium | только чтение | приёмка по диффу |
| `docs` (`wiki_publish`) | Haiku | только чтение | страница документации по материалам плана |
| `main` | сам оркестратор | — | общие файлы, рискованное |

Модель, effort и таймаут тира переопределяются в `~/.config/claude-planner/config.json`:

```json
{"tiers": {"code": {"model": "claude-sonnet-5", "effort": "low"}, "review": {"model": "sonnet", "effort": "high"}}}
```

Воркерам запрещены `git commit/push/reset/checkout/stash`, `sudo`, `ssh`, `docker`, установка пакетов; читающим тирам доступен только перечень читающих команд.

## Инструменты (11)

`plan_scout`, `plan_init`, `plan_update`, `plan_run`, `plan_jobs`, `plan_worker`, `plan_verify`, `plan_skip`, `plan_show`, `plan_review`, `plan_finish`. Протокол для модели — `skill/planner/SKILL.md`. Каждый ответ кончается строкой «Дальше: …» с детерминированной подсказкой следующего шага.

## Гейты

- Пункт воркера обязан назвать `files`; два пункта с общим файлом одновременно не стартуют.
- `depends_on` образует волны; цикл или несуществующий id — ошибка создания плана.
- Перед приёмкой и перед закрытием все проверки гоняются заново (одинаковые — один раз); регрессия возвращает пункт в `failed`.
- Приёмщик отклоняет план только блокерами; вердикт считается по списку замечаний, а не по слову модели. Не больше 3 отказов, дальше — решение пользователя (`plan_finish(user_approval=…)`).

## Когда обстоятельства изменились

Перестраивать план можно свободно: `plan_update` принимает `add`, `update` (любые поля пункта, `reopen`), `title`, `goal`. Всё, что снимает гейт, требует `user_approval` — дословной цитаты ответа пользователя:

| Действие | Что происходит |
|---|---|
| `plan_skip(item_ids, reason, outcome="skipped")` | пункт не делаем; его воркер останавливается |
| `plan_skip(..., outcome="done")` | результат принят без проверки (пометка `manual`); в повторные прогоны перед приёмкой и закрытием такой пункт не попадает |
| `plan_update(remove=[ids])` | пункты удаляются из плана, зависимости на них снимаются |
| `plan_finish(summary, user_approval)` | закрытие без приёмки и/или вики; пункты должны быть закрыты, проверки гоняются; снятые гейты пишутся в `user_override` |
| `plan_finish(summary, user_approval, force=true)` | закрытие как есть: воркеры останавливаются, открытые пункты → `skipped`, проверки не гоняются, план помечается `closed_as_is` |

Цитата сверяется только на непустоту — это запись решения в `plan.json` и в историю, а не криптографическая подпись.

## Параллельность

- Все готовые пункты одной волны стартуют одним `plan_run`, до 4 воркеров сразу; разведчики — до 4 параллельно.
- Пока у оркестратора есть свои пункты `main` в работе, `plan_run` не ждёт воркеров, а возвращается сразу (`wait=true` — ждать принудительно).
- `plan_init` и `plan_update` предупреждают, если план воркеров выродился в цепочку или два пункта одной волны делят файл.

## Хуки (`planner/hooks.py`)

| Событие | Что делает |
|---|---|
| `PreToolUse(Read)` | запрещает читать целиком файл кода длиннее 500 строк (`CPLAN_READ_CAP`, 0 — выключить) |
| `PreToolUse(Edit\|Write\|NotebookEdit)` | правка файла проекта без открытого плана отклоняется с требованием завести план; субагенту — вернуть отчёт основной сессии (`CPLAN_PLAN_GATE=0` — выключить). Проект — git-репозиторий, папка с `.cplan` или папка первого уровня в `~/projects`, `~/work`, `/mnt/datadisk/Projects` (`CPLAN_PROJECT_DIRS`). Свободны: файлы вне проектов, `~/.claude`, `.claude/` и `.cplan/` проекта, исходники самого планера |
| `PostToolUse` | запоминает, какие планы ведёт сессия; при выключенном гейте один раз подсказывает про план после 4-го файла без плана |
| `UserPromptSubmit` | сбрасывает счётчики хода |
| `Stop` | не даёт закончить ход с недоведённым планом, если его вели в этом ходу; пауза — `plan_update(hold=…)`; не больше двух блокировок подряд |
| `SubagentStart` | встроенному субагенту (Agent: `worker-*`, `designer`, `Explore`…) вшивает действующий план проекта и сессии — цель, пункты, какие файлы сейчас у воркеров — и правила работы внутри него; плана нет — молчит |
| `PreToolUse(mcp__planner__.*)` | субагенту запрещены `plan_init/update/skip/finish/run/verify/review/worker` и `wiki_publish`: план ведёт основная сессия, согласие пользователя субагент получить не может (`CPLAN_AGENT_GATE=0` — выключить); читать план (`plan_show`, `plan_jobs`, `plan_scout`, `wiki_pages`) можно |

Любая ошибка хука — fail-open. Гейт видит только `Edit`/`Write`/`NotebookEdit`: правку через Bash (`sed -i`, перенаправление) он не ловит, воркеров планера (`claude -p` без пользовательских настроек) не касается.

## Окно контекста

`install.py install` ставит в `~/.claude/settings.json` `autoCompactWindow: 300000` (константа `CONTEXT_WINDOW`): основная сессия сжимается на 300k вместо миллиона, встроенные субагенты наследуют это окно. Состояние плана переживает сжатие — его отдаёт `plan_show`. Проверить: `/autocompact` в сессии. Воркеры планера идут на Sonnet/Haiku/Opus без `[1m]` и пользовательских настроек не читают — их окно задаёт модель.

## Plane

Для отслеживаемых планов заводится одна задача с чек-листом; при закрытии она уходит в «В проверке». Реквизиты: `~/.config/claude-planner/plane.env`, при отсутствии — `~/.config/agy-planner/plane.env` (`PLANE_BASE_URL`, `PLANE_API_KEY`, `PLANE_WORKSPACE_SLUG`). Сбой Plane работу плана не останавливает.

## Установка и откат

```bash
python3 install.py all      # MCP, скилл, хуки, cplan + минимальный CLAUDE.md + уборка мёртвого груза
python3 install.py check    # что установлено и работает
python3 install.py restore ~/.claude/backups/claude-planner-<дата>   # вернуть как было
```

Ничего не удаляется: всё переносится в бэкап с манифестом.

## Терминал

```bash
cplan watch ~/projects/foo   # план и воркеры, обновление раз в 2 с
cplan logs 3 ~/projects/foo  # отчёт и шаги воркера пункта 3
```
