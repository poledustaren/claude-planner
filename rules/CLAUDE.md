# Правила

Минимум. Всё, что можно проверить кодом, проверяют хуки и MCP `planner`, а не этот текст.

## Память
- Запрос называет проект, сервер, бота, модуль или инструмент → первым вызовом `mcp__hindsight__recall` (query — тема запроса, `max_tokens` 1500). Локальная мелочь без именованных артефактов — без recall.
- После решения, которое пригодится позже (грабли, архитектура, доступы) → `mcp__hindsight__sync_retain`: проверенный факт с якорем (сервер, путь, команда, версия), теги — проект, дата, домен. Гипотезы не сохраняй.

## План
- Правки в проекте — только по плану (скилл `planner`, MCP `planner`). Нужен ли план, решает хук: правку файла проекта без открытого плана он отклонит. Вопросы, диагностика и инфраструктура через `devopsmcp` идут без плана.
- Вес плана выбираешь ты и меняешь по ходу: отладка, эксперимент, не код, мелкая правка в одном файле, доделка — пункт без проверки (`light`), закрывается записью «что сделал»; работа с наблюдаемым результатом — пункт с проверкой: один файл — сам, независимые части — воркерам Sonnet; незнакомый код — разведка на Haiku; от 4 пунктов — приёмка. Планер сам ведёт задачу и паспорт проекта в Plane; документацию в Outline (`wiki_publish`, пишет дешёвый воркер) требует от 4 пунктов и всегда, когда меняется запуск, контракт или схема; для багфиксов она не нужна.
- Встроенный `Agent` — только для того, что планер не покрывает: дизайн, инфраструктура, исследование в вебе.

## Код
- Сначала найди, потом читай: `rg`, `fd`, `ast-grep`; `Read` — с `offset`/`limit`. `grep -r`, `find`, `cat` не используй.
- Правь минимальным диффом в стиле соседнего кода. Не расширяй задачу.
- «Работает» — только про то, что проверено командой в этой сессии. Иначе пиши «не проверено».
- Независимые команды — одним вызовом Bash или параллельными вызовами. Вывод фильтруй (`rg`, `tail`, `jq`), сырые логи и дампы в контекст не тащи.
- Секреты — в env или Vault, не в коде и не в памяти.

## Инфраструктура
- Только через MCP `devopsmcp`: `search` / `landing` — найти узел, `exec_on` / `read_logs` / `diagnose` — смотреть, `credentials` — реквизиты из Vault. Карта и доступы — скилл `infra-ops`.
- Читать и диагностировать можно свободно. Любое изменение (рестарт, конфиг, деплой, запись в БД) — `propose_action` и явное подтверждение пользователя.
- Подтверждение — диалог «да/нет» хука на `apply_action` (`~/.claude/bin/devopsmcp-yn.py`), фразу «APPROVE …» у пользователя не проси. Опиши заявку или план одной-двумя строками и сразу вызывай `apply_action(id, operator_message="")`: фразу подставит хук после «да». План — один вопрос на весь план, шаг из стоп-листа — отдельный. Отказ в диалоге — это «нет»: не повторяй вызов, спроси, что поменять. Исключение — ночное окно: фразу «ОКНО …» пишет только пользователь.
- Выборки из БД и логов агрегируй на сервере, сюда — только сводку.
- Не трогай ssh, файрвол и сеть узла без второго канала доступа. Процессы завершай по PID (`pgrep -af`), широкий kill по имени запрещён хуком.

## Проекты и git
- Проекты лежат в `~/projects`, `~/work`, `/mnt/datadisk/Projects`. Работай в папке проекта, не в `~`.
- Коммит и пуш — только по просьбе. Формат: `<type>: <описание>` (feat/fix/refactor/docs/chore/ci), тело — зачем. Атрибуция отключена.
- Перед коммитом — `git diff --staged` глазами. Общие ветки не ревертить и не `reset --hard` без согласования; ascore в `master` не сливаем.
- GitHub и GitLab — через `git-tool` (скилл `wellsoft-cli-reference`). Перед мержем смотри push-пайплайн самой ветки.
